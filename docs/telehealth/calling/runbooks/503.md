# Runbook: Calling 503 Decision Tree

## Current verified local behavior

`GET /api/communication/v1/calls?asUser=dev` is currently `405 Method Not Allowed`, because the route is POST-only. A safe replay of a valid local `POST /api/communication/v1/calls?asUser=dev` returns controlled `503 TELEPHONY_UNAVAILABLE` because no approved provider is configured. See [the root-cause record](../01-503-root-cause.md).

## First-response procedure

1. Preserve the request method, path, status, content type, safe response code, correlation ID, time, environment, and opaque call ID. Do not record secrets/PHI.
2. Identify whether the result is a known local-development behavior, an API-contract gap, an authorization/gateway failure, a calling-store failure, a media-provider failure, realtime failure, TURN failure, or an unexpected application error.
3. Check the dependency health model and relevant sanitized logs/traces once deployed. Do not restart services or change provider/network configuration without approved operations procedure.

```text
HTTP result
  |
  +-- 405 on GET /api/communication/v1/calls?
  |     -> current API gap: no GET handler; not a media/provider 503
  |
  +-- 503 TELEPHONY_UNAVAILABLE in current local seam?
  |     -> expected no-provider behavior; preserve truthful UI and plan provider-independent history
  |
  +-- 503 CALL_STORE_UNAVAILABLE (target)?
  |     -> database/control-plane incident; history may not be fabricated; invoke data/platform escalation
  |
  +-- 503 MEDIA_PROVIDER_UNAVAILABLE (target)?
  |     -> history should remain available; invoke media-provider runbook
  |
  +-- 503 REALTIME_PROVIDER_UNAVAILABLE (target)?
  |     -> committed call remains; ringing may degrade; inspect outbox/realtime health
  |
  +-- 503 TURN_UNAVAILABLE (target)?
  |     -> follow TURN runbook; do not claim fallback
  |
  +-- gateway/authentication/unknown?
        -> validate route, session/authorization policy, correlation trace, safe error mapping
```

## Expected behaviors after durable implementation

| Condition | Required behavior |
|---|---|
| Media provider down | History remains `200` where store/authorization are healthy; new media action returns a controlled unavailable response. |
| Database/control-plane down | Controlled `CALL_STORE_UNAVAILABLE`; no panic, empty success list, or speculative ringing. |
| Realtime delivery down | Committed history remains; notification delivery is visibly degraded/retried according to policy. |
| Invalid state or answer race | Deterministic conflict (`409`/documented code), not generic `503`. |
| Unauthorized context | `401`/`403`/withheld `404` according to approved policy, not a provider error. |

## Closure criteria

Document root cause, affected dependency, remediation, test evidence, rollback/follow-up, and policy impact. A generic 503 must never be suppressed to make the UI appear healthy.
